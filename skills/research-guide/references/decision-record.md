# Research decision record

Use one compact record per active question. Reuse an existing project format if it carries the same information. Unknown fields should say what is missing and whether it changes the decision.

This reasoning record complements the four-stage workflow record. It cannot substitute for user acceptance. Record the current stage, accepted subfield/question revisions, accepted corpus snapshot when applicable, and whether the work is a candidate or accepted artifact. See [stage-gates.md](stage-gates.md) before advancing.

Add the current intake revision and distinguish completed/reported work, inspected observations, interpretations, and plans. For a consultation, link its question/evidence revision, product route, requested and verified actual model, returned answer, and citation checks. Record which recommendations were adopted or rejected and why, what changed in the active artifact, and what remains unresolved. Keep a pending answer distinct from a completed, verified, or applied answer. Model completion does not accept a stage.

## Current position

| Item | Record |
|---|---|
| Objective and scope | The larger aim and the conditions this question covers. |
| Current question | The specific unknown and the decision its answer changes. |
| Stage | Orienting, learning, framing, designing, evaluating evidence, or revising. |
| Resources | Confirmed access, expertise, constraints, and explicitly provisional assumptions. |
| Existing knowledge | Accepted premises, disputed claims, and nearest prior work, with sources. |
| Evidence boundary | Search date/scope, full-text access gaps, and unverified premises. |
| Candidate answers | Plausible explanations, descriptive outcomes, or solution approaches. |
| Main bottleneck | The uncertainty currently preventing progress. |
| Next action | One task with input, output, completion criterion, and resource estimate. |
| Decision after action | Outcomes that support continuing, changing approach, or stopping. |

## Evidence entries

Give consequential evidence a stable local ID. Record the claim, origin, inspected location, relevant conditions, access level, observation, interpretation, assumptions, uncertainty, and contradictory evidence. For project data, include the data or analysis version. Mark planned work separately from completed work. An AI suggestion is a hypothesis or proposal until checked.

Useful access labels are metadata only, abstract read, full text inspected, and specific evidence checked. These are different achievements; do not count them all as papers read.

## Update after work

Record the date, what actually happened, deviations from the plan, what changed in the evidence, and the decision with its reason. Preserve the prior criterion when revising it. A changed threshold after seeing a result must not be presented as a prior prediction.

Separate two kinds of completion:

- The assigned task is complete when its agreed artifact and checks are delivered.
- The scientific question is resolved only to the extent the evidence supports an answer within a stated scope.

A completed plan may leave the science unresolved. An unsuccessful study may still justify a useful decision.
